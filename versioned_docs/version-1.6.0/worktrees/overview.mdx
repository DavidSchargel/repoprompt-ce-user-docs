A **Git worktree** is a separate working directory attached to the same repository. Each checkout has its own files, index, and checked-out branch or commit, while sharing Git history. You can work on different branches at once without repeatedly switching branches in your main checkout.

RepoPrompt CE creates worktrees through Agent Mode and the MCP `manage_worktree create` tool, with optional copying of local setup files.

RepoPrompt can create worktrees for MCP tools and Agent Mode. App-managed worktrees are placed in the `.repoprompt-worktrees` container unless you deliberately choose an external path. A worktree gives an agent an isolated checkout while the main checkout and other worktrees remain available for parallel work.

On APFS, RepoPrompt automatically attempts copy-on-write cloning when the new worktree starts from the same tree as a clean source checkout on the same volume. Tracked files initially share disk blocks with the source and consume additional space only when changed. RepoPrompt verifies the cloned checkout by refreshing its index and requiring a clean Git status. It uses an ordinary Git checkout when the source is dirty, the requested base differs, or repository features such as sparse checkout, submodules, Git LFS filters, special line-ending or encoding attributes, hooks, path collisions, different volumes, or an external destination make cloning unsuitable. Set `clone_tracked_checkout=false` when checkout speed matters more than disk space.

## Copying local ignored files with `.worktreeinclude`

Add `.worktreeinclude` at the main repository root using `.gitignore` patterns. Matching ignored files are copied; tracked edits are excluded. MCP creation can explicitly include matching untracked files with `copy_worktree_include_untracked_files=true`.

Patterns support comments, directory rules, globs, and `!` negations. A file must pass both checks: Git must already treat it as ignored, and the final matching `.worktreeinclude` rule must include it. RepoPrompt copies regular files individually, using APFS clones when available and byte copies otherwise. It does not copy tracked files, ordinary untracked files by default, symlinks, unsafe paths, or files that would overwrite an existing destination.

Copying is limited to RepoPrompt-managed worktrees. An external worktree created with `allow_external_path=true` is still created, but `.worktreeinclude` files are not copied there. Successful copying is silent; if a copy cannot be completed, the worktree remains and `manage_worktree create` may report a warning. Agent Mode and descriptor-only flows record production-safe diagnostics.

## Be careful with broad patterns

There is no copy-size or file-count limit. Keep patterns narrow to avoid duplicating large caches.

For details, see the [RepoPrompt CE worktrees guide on GitHub](https://github.com/repoprompt/repoprompt-ce/blob/main/docs/worktrees.md).
