Modern coding agents optimize for raw _convenience_: you type a prompt, and the agent immediately starts running shell commands and editing files. On small scripts, this feels magical. But on production codebases, unguided autonomous agents frequently hit a wall.

RepoPrompt was explicitly architected to solve the **top failure modes in standard coding agents**:

---

## The Top Failure Modes in Standard Coding Agents

### 1. Context Rot & Hallucinations

As conversation histories and file dumps expand past a model's effective sweet spot (64k–128k tokens), attention degrades sharply. When forced to reason inside a bloated context window filled with dead-end searches, models invent non-existent APIs, misremember types, and hallucinate implementations.

- **How RepoPrompt solves it:** The **Context Builder** discovery agent curates a focused, token-budgeted selection (defaulting to 120,000 tokens) before the reasoning model starts, ensuring 100% of the model's thinking capacity is spent on the solution. See [Reliable, Useful Results](./overview/how-it-really-works.mdx#1-reliable-useful-results-context-over-convenience).

### 2. "Lost in the Middle" Forgetting

Due to the U-shaped attention curve of transformers, models strongly weight instructions at the very beginning and very end of a prompt, but drop accuracy by 30%+ on vital constraints, types, or instructions buried in the middle of a large payload.

- **How RepoPrompt solves it:** **Instruction Sandwiching** duplicates `<user_instructions>` at both the top and bottom of assembled prompts, surrounding compact Tree-sitter **Code Maps** and non-contiguous **Line Slices**. See [Advanced Context Engineering](./overview/how-it-really-works.mdx#2-advanced-context-engineering).

### 3. MCP & Tool Context Bloat

Unbounded tool schemas (schema bloat) and voluminous raw tool outputs (like 500-line `grep` logs) flood the message buffer, burning token budgets and destroying prompt caches before the model even begins reasoning.

- **How RepoPrompt solves it:** Strict separation of **Model Context** (curated workspace selection) from **Tool Context** (noisy command history), preloaded compact tool catalogs, non-blocking auto-selection, and disabling redundant native file tools. See [Model Context vs. Tool Context](./overview/how-it-really-works.mdx#3-model-context-vs-tool-context).

### 4. Multi-Turn Drift on Large Tasks

As a single agent loops through dozens of iterative edits across 30+ turns, early constraints fade and small misinterpretations compound, causing the agent to wander away from the original goal or introduce conflicting changes.

- **How RepoPrompt solves it:** A **Coordinator vs. Worker** architecture (`/rp-orchestrate`) that breaks work into discrete 1–4 file work items for fresh sub-agents, coupled with the **Phase Gate Invariant** and event-driven **Oversight Auto-Wake**. See [Multi-Turn & Long-Horizon Operation](./overview/how-it-really-works.mdx#4-agents-operating-over-multiple-turns-and-longer-time-horizons).

### 5. Compaction Amnesia

Naive token-limit compaction summarizes conversation history by focusing on _what was done_, frequently stripping negative side constraints (e.g., _"never modify the public API"_) and raw file details, causing post-compaction regression loops.

- **How RepoPrompt solves it:** Agent-initiated `self_compact` at clean turn boundaries with dedicated `<repoprompt_self_compact_note>` continuation delivery, `oracle_chat_log` recovery, and `<forked_session>` handoffs. See [Compaction Architecture](./overview/how-it-really-works.mdx#5-compaction-and-preventing-compaction-amnesia).

### 6. Single-Model Blind Spots

Forcing a single model to act as search engine, architect, and coder causes failures—especially when reasoning models (trained to "think then act" in consensus) are forced to execute tool calls mid-thought.

- **How RepoPrompt solves it:** Tool-less **Oracle** reasoning paired with tool-native CLI agents, 4 specialized **Agent Roles** (`explore`, `engineer`, `pair`, `design`), parallel **Multi-Oracle Rosters** (up to 5 models) with reconciliation guidance, and local **Usage Balancing**. See [LLM Variations & Limitations](./overview/how-it-really-works.mdx#6-variations-and-limitations-of-large-language-models-llms).

### 7. Diff-Only Review Blindness

Reviewing isolated Git patches without surrounding repository context creates high false-positive noise on style while completely missing breaking changes to callers one hop away from the diff.

- **How RepoPrompt solves it:** Materialized selectable diff artifacts (`MAP.txt`, `all.patch`, per-file patches) combined with curated codebase context (callers, callees, and type contracts) in `/rp-review`. See [Codebase-Context Code Reviews](./overview/how-it-really-works.mdx#7-code-reviews-diff-only-vs-codebase-context-reviews).

### 8. Over-Engineered Simple Edits

Triggering heavy multi-agent orchestration, full discovery pipelines, or multi-model planning for trivial, localized 1–3 file fixes wastes time, tokens, and developer patience.

- **How RepoPrompt solves it:** Built-in **Fast Path** rules in `/rp-build` and `/rp-investigate`, the **~30-line / ≤ 2-file threshold** in `/rp-orchestrate`, and disabled-by-default `context_builder` on routine turns. See [When RepoPrompt Would Not Be Helpful](./overview/how-it-really-works.mdx#8-when-repoprompt-would-not-be-helpful).
