**Bring your code, context, and AI coding tools together.**

RepoPrompt gives you a well-thought-out, unified workspace for exploring a repository and working with your go-to AI coding tools. Use its first-class tooling to explore an extensive repo, trace unfamiliar code, work through an architectural decision, review a series of changes, or coordinate work across coding agents you already use.

The macOS application is **free and open source**. Connect your own coding-runtime account, API provider, or local model service; [AI service costs](./faq/pay-for-services.mdx) depend on the connection you use.

## Give your coding work the right tools and the right context

Before any coding agent can make production-ready changes, it needs to understand the code already there: the relevant files, their interfaces, the changes in progress, and the constraints that matter. We all know that finding and sharing that context can take longer than writing the plan or prompt.

RepoPrompt helps you build a focused view of the task and assemble that context accurately and narrowly so you get the best results from your favorite models from your preferred providers. It gathers full files when implementation details matter, slices when only a few lines are relevant, and delivers Code Maps when structure and signatures are enough. Add Git changes and clear instructions to show the model what you want it to examine.

## Start with the task you need to finish

Choose a built-in workflow from the welcome cards or the **Workflow** selector, then describe what you want to accomplish. Let RepoPrompt go from there.

| What you want to do                      | Where to start                                                                           |
| ---------------------------------------- | ---------------------------------------------------------------------------------------- |
| Coordinate a larger piece of work        | **Orchestrate** breaks down the task, delegates work, and checks the results.            |
| Check changes for bugs and regressions   | **Review** examines the change with its surrounding code.                                |
| Understand a bug or unfamiliar behavior  | **Investigate** gathers evidence and explores the relevant code.                         |
| Plan a substantial change before editing | **Deep Plan** develops an implementation plan grounded in the repository.                |
| Build a feature or fix                   | **Plan & Build** guides research, planning, and implementation.                          |
| Improve code structure                   | **Refactor** focuses on preserving intended behavior while improving the implementation. |
| Get an independent perspective           | **ChatGPT Export** prepares context for a conversation outside RepoPrompt.               |

## Make RepoPrompt Your Partner

1. **Describe the task.** The Context Builder gathers relevant code, and Oracle drafts an execution plan. A narrow context window and a double-checked plan is key for the best results.
2. **Divide the work.** The Orchestrator assigns tasks with clear file boundaries. No hidden "Thinking..." output here.
3. **Implement.** Agents work sequentially or in parallel from a shared plan, with the Orchestrator steering progress. The division of tasks and clarity that the Orchestrator offers is part of our "secret sauce."
4. **Verify.** The Orchestrator checks the results against the plan and continues until complete. All together, this is what yields production-quality code.

## Coordinate larger changes without losing sight of them

RepoPrompt overcomes the AI-assisted nightmare of big edits. For a larger change, you can use separate sessions for investigation, implementation, and review. **Overseer Mode** lets a coordinating conversation follow linked sessions and direct the next steps.

Use **worktrees** when parallel tasks need separate checkouts; separate conversations can still edit the same checkout. Review the work, merge it into the intended target, and verify the combined result.

[Coordinate sessions with Overseer →](./overseer/overview.mdx) · [Create and use a worktree →](./worktrees/create-and-use.mdx) · [Review and merge the result →](./worktrees/review-and-merge.mdx)

## Keep control as the work develops

- **Make the request clearer.** Use [Interviewer](agent-mode/interviewer.mdx) to resolve open questions or [Re-Prompter](agent-mode/re-prompter.mdx) to refine a draft before sending.
- **Show the problem.** Attach a [screenshot or mockup](agent-mode/image-support.mdx). Eligible Codex sessions can also use [Computer Use](agent-mode/computer-use.mdx) for tasks that need the visible interface.
- **Choose how the model works.** Set the [model and reasoning effort](agent-mode/model-and-effort.mdx) yourself, or configure [Agent Decisions](agent-mode/model-router.mdx) for eligible new tasks.
- **Review the decisions that matter.** Inspect [approval requests and edit reviews](agent-mode/approvals.mdx), then return to [session history](agent-mode/session-history.mdx) when you need the context behind a result.

## Use the connection that fits your work

Connect a supported coding runtime for implementation, a direct API for model features, or a local model server. Configure Oracle consultations separately when you want another model to assess a plan or review the code.

The **Providers & Models** reference explains what each integration needs and what it supports. Available models depend on your connected accounts or APIs you bring to the table. You can start with a focused task and adjust the settings as you go; you do not need to choose every model and experiment with thinking levels and settings before trying.

## Try it on one real task

Start with a question you can evaluate: understand an unfamiliar function, investigate a reproducible bug, or review a small change. A narrow first task makes it easier to see what RepoPrompt adds to your existing workflow.

1. **Open your project** and connect the provider you want to use.
2. **Describe the outcome.** Include the behavior you care about, known constraints, and how you will check the result.
3. **Choose the workflow and location.** Use a separate worktree when you want an isolated checkout.
4. **Inspect and guide the work.** Review the selected context, answer questions, and check the resulting code and test results.
