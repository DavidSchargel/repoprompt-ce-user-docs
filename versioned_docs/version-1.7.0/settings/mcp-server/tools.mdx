Open **Settings → MCP Server → Tools**. RepoPrompt defines **31 total domain tools**, of which **21 are advertised** to standard external MCP clients (composed of **3 global tools** — `app_settings`, `bind_context`, and `manage_workspaces` — and **18 window-scoped tools**). The remaining **10 policy-gated and sub-agent internal tools** are reserved for eligible Agent Mode sessions and cross-session oversight.

The screenshots on this page (`tools.png` and individual `tools-*.png` captures) are historical captures showing the 21 advertised tool descriptions expanded. There are minor differences in parameter naming (such as `search_pattern` vs `pattern` and regex flag descriptions) and legacy window-selector wording compared to the latest code (`MCPDomainToolCatalog.swift`). For current arguments, response behavior, and examples, see the [MCP Server Tools Reference](../../mcp-server/mcp-tools.mdx).

## Access, search, and availability

**Enable MCP tools for this window** is the same window-level gate as the switch on [MCP Server](./mcp-server.mdx). Turning it off disables the individual switches in this pane.

Individual tool switches are saved in an **app-wide** disabled-tools list shared by windows. They are not separate per-window preferences, despite the captured pane's introductory wording. Changes notify connected clients that the tool list changed.

**Search tools…** filters names and descriptions without changing enablement. The count shows how many tools are enabled; with a search, the list also shows how many matching tools are enabled. **More…** expands a long description and **Show less** collapses it. Expanding a description does not run the tool.

If the list says **No tools discovered**, start the MCP server and connect a client. Tools restricted to particular agent contexts are omitted from this general settings list. Enabling a tool does not bypass workspace permissions or the tool's own input and approval checks.

## agent_explore

Launches short-lived, read-only child agents for narrow repository investigations. Each gets a fresh context and the Explore role. Operations are `start`, `poll`, `wait`, and `cancel`; a batch can start multiple independent probes. See the [`agent_explore` contract](../../mcp-server/mcp-tools.mdx#agent_explore).

Explore children cannot edit files, call Oracle, or spawn more agents. They inherit worktree bindings by default, with an opt-out. When Model Router is enabled, new explore children can be routed across eligible targets.

![agent_explore switch and expanded description for read-only exploration agents](../images/tools-agent-explore.png)

## agent_manage

Lists agent choices, model and role mappings, sessions, and workflows. It also reads session logs, exports handoffs, creates or resumes sessions, stops sessions, and cleans up eligible MCP-created sessions.

`list_agents` supplies the current role mappings and exact model identifiers. `get_log` reads transcript turns; handoff export prepares context for continuing elsewhere. Cleanup targets specified MCP-originated sessions and does not delete user-created sessions. See the [`agent_manage` contract](../../mcp-server/mcp-tools.mdx#agent_manage).

![agent_manage switch and expanded agent catalog, session management, and workflow description](../images/tools-agent-manage.png)

## agent_run

Starts and controls Agent Mode runs. `start` creates a new session; `steer` continues an existing one. `poll` checks immediately, `wait` waits for completion or input, `respond` resolves a pending interaction, and `cancel` stops an active run.

Use the returned session and interaction identifiers for follow-up calls. Role labels use the configured Agent Models mapping; an exact compound model identifier pins a target. Model Router can choose for eligible starts using a role or omitted model. See the [`agent_run` contract](../../mcp-server/mcp-tools.mdx#agent_run) and [Model Router](../agent-mode/agent-decisions.mdx).

![agent_run switch and expanded start, wait, steering, and interaction description](../images/tools-agent-run.png)

## app_settings

Reads and updates the allowed set of app-wide preferences. `list` discovers settings, `get` reads values, `set` writes one key, and `options` discovers supported choices where available.

Only exposed settings can be changed; invalid or out-of-range values are rejected. The current implementation also exposes notification preferences, matching the [Notifications](../general/notifications.mdx) pane. See the [`app_settings` contract](../../mcp-server/mcp-tools.mdx#app_settings) and the full [App Settings Tool reference](../../mcp-server/mcp-app-settings.mdx).

![app_settings switch and expanded allowed preferences and operations](../images/tools-app-settings.png)

## apply_edits

Edits file contents using exactly one mode: replace the whole file with `rewrite`, replace matching text with `search` and `replace`, or apply a list of `edits`. Mixing modes is rejected.

Replacements are literal text. A rewrite can opt into creating a missing file with `on_missing`; otherwise a missing file is an error. Enable this tool only when clients should be able to request file-content changes under the applicable permissions. See the [`apply_edits` contract](../../mcp-server/mcp-tools.mdx#apply_edits).

![apply_edits switch and expanded rewrite, replacement, and multiple-edit modes](../images/tools-apply-edits.png)

## bind_context

Lists available contexts, reports the connection's current binding, and binds a client to a specific workspace context. Prefer absolute workspace root paths in `working_dirs`, or use a returned `context_id`.

The binding is retained for that MCP connection. Switching the visible tab does not redirect an existing binding. The captured description includes legacy window selectors; newer builds make this a global context tool without an app-window selector. Use the schema advertised by your connected build. See the [`bind_context` contract](../../mcp-server/mcp-tools.mdx#bind_context) and [Connection Management](../../mcp-server/mcp-connections.mdx#context-binding).

![bind_context switch and expanded context listing and binding description](../images/tools-bind-context.png)

## context_builder

Runs a Context Builder agent to discover relevant code, select files within a token budget, and prepare a clarified prompt. Describe the task and known constraints; exhaustive file selection beforehand is not required.

The default or `clarify` response returns context for later use. `question`, `plan`, and `review` request a follow-up answer, implementation plan, or review. Response export can produce a shareable file. See the [`context_builder` contract](../../mcp-server/mcp-tools.mdx#context_builder). Configure discovery in [Context Builder](../agent-mode/context-builder.mdx) and its model in [Agent Models](../agent-mode/agent-models.mdx).

![context_builder switch and expanded discovery, response type, and export description](../images/tools-context-builder.png)

## file_actions

Creates, moves, or deletes files using absolute paths. A created file is automatically selected. Creation rejects existing files unless overwrite is explicitly requested; a move fails when the destination already exists.

Deletion moves files or folders to the macOS Trash, where they remain recoverable until Trash is emptied. Moving a file transfers its selection state. See the [`file_actions` contract](../../mcp-server/mcp-tools.mdx#file_actions).

![file_actions switch and expanded create, delete, and move behavior](../images/tools-file-actions.png)

## file_search

Searches file paths, file contents, or both. `auto` selects the mode from the pattern; explicit modes are `path`, `content`, and `both`. Filters can limit extensions and directories or exclude paths.

Regex matching is available; set `regex=false` for literal content matching or glob-style path matching. Result and output limits can truncate large searches. For an agent bound to a worktree, filesystem searching uses that worktree even when returned paths retain the canonical workspace form. See the [`file_search` contract](../../mcp-server/mcp-tools.mdx#file_search).

![file_search switch and expanded path, content, matching, and filter options](../images/tools-file-search.png)

## get_code_structure

Returns root-local committed code structure for supplied files or directories, or the current selection when paths are omitted. It can include signatures and expand relationships through `uses`, `used_by`, or both.

Output size and relationship depth limit the response. If a result reports truncation, request a larger size or narrow the seeds. Update-pending information distinguishes a usable committed graph from work still being refreshed. See the [`get_code_structure` contract](../../mcp-server/mcp-tools.mdx#get_code_structure).

![get_code_structure switch and expanded structure, relationship, signature, and output-size options](../images/tools-get-code-structure.png)

## get_file_tree

Returns a text directory tree or lists loaded root folders. Tree modes include automatic sizing, full output, folders only, and selected files with their parent directories.

Use `path` to focus a subtree and `max_depth` to limit traversal. Selection and Code Map markers describe workspace state. Bound-worktree searches follow the session's worktree. See the [`get_file_tree` contract](../../mcp-server/mcp-tools.mdx#get_file_tree).

![get_file_tree switch and expanded tree types, modes, depth, and selection markers](../images/tools-get-file-tree.png)

## git

Provides read-only Git inspection: `status`, `diff`, `log`, `show`, and `blame`. Diff comparison choices include staged, unstaged, uncommitted, branch, and merge-base comparisons. Detail levels range from summary to full patches.

Artifact output writes review files and can make them available for later context selection. This tool does not commit or push. Use repository selectors when working with multiple roots; some history operations use the primary repository only. See the [`git` contract](../../mcp-server/mcp-tools.mdx#git).

![git switch and expanded read-only status, diff, log, show, blame, and artifact options](../images/tools-git.png)

## history

Queries past Agent Mode sessions across saved workspaces. Operations list sessions, search transcripts and summaries, retrieve a bounded session excerpt, and calculate time spent. These operations are read-only.

Use workspace filters when you want a narrower scope; binding the MCP connection to a window does not itself restrict historical searches. Time calculations use the [Advanced idle threshold](../general/advanced.mdx#history-time-tracking) unless overridden per query. See the [`history` contract](../../mcp-server/mcp-tools.mdx#history).

![history switch and expanded cross-workspace session search, transcript, and time analytics](../images/tools-history.png)

## manage_selection

Changes the file context used by tools: get, add, remove, replace, clear, preview, promote, or demote selections. Files can be represented by full content, line slices, or Code Maps.

`set` can replace a selection, so use incremental `add` and `remove` when preserving existing context matters. Multi-root paths can use a root-name prefix to disambiguate files. Git artifact paths have stricter matching and representation limits than ordinary workspace files. See the [`manage_selection` contract](../../mcp-server/mcp-tools.mdx#manage_selection).

![manage_selection switch and expanded selection operations, full files, slices, and Code Maps](../images/tools-manage-selection.png)

## manage_workspaces

Lists, creates, switches, hides, restores, and deletes workspaces, and manages their folders and Compose tabs. Hiding keeps a workspace recoverable; deleting a saved workspace is permanent.

`bind_context` is the canonical tool for connection binding. Legacy tab-listing and tab-selection operations remain compatibility paths. Background tab creation can avoid stealing focus; setting `focus=true` visibly switches the user's tab. See the [`manage_workspaces` contract](../../mcp-server/mcp-tools.mdx#manage_workspaces) and [Connection Management](../../mcp-server/mcp-connections.mdx).

![manage_workspaces switch and expanded workspace and Compose-tab lifecycle operations](../images/tools-manage-workspaces.png)

## manage_worktree

Lists, inspects, creates, and binds Git worktrees to Agent sessions. Merge operations use the session's bound source worktree and can preview, apply, inspect status, continue, or abort a merge.

Preview does not mutate the repository. Apply uses the returned operation identifier and requires the applicable confirmation; plain MCP callers use `confirm_preview=true`. Worktree binding is session-specific, so identify the intended session and repository when there is ambiguity. See the [`manage_worktree` contract](../../mcp-server/mcp-tools.mdx#manage_worktree) and [Worktrees](../../worktrees/overview.mdx).

![manage_worktree switch and expanded Git worktree binding, merge preview, apply, and confirmation behavior](../images/tools-manage-worktree.png)

## oracle_send

Consults Oracle for questions, planning, or review. Without an explicit chat or new-chat request, it resumes the selected eligible conversation, falling back to the most recent eligible conversation. `new_chat=true` starts fresh.

A model override applies only to an explicit new conversation. Exposed Model Presets can select a complete Oracle roster and Chat Preset. Response export writes a shareable file for another agent. Agent Mode can expose `ask_oracle` for the corresponding task. See the [`oracle_send` contract](../../mcp-server/mcp-tools.mdx#oracle_send).

![oracle_send switch and expanded conversation continuation, model selection, and export behavior](../images/tools-oracle-send.png)

## oracle_utils

Provides read-only Oracle helpers: discover available model choices and list Oracle/chat sessions. It does not send an Oracle message. Use `oracle_send`, or `ask_oracle` when exposed in Agent Mode, to request a response.

![oracle_utils switch and expanded read-only model and session listing](../images/tools-oracle-utils.png)

See the [`oracle_utils` contract](../../mcp-server/mcp-tools.mdx#oracle_utils).

## prompt

Gets, replaces, appends to, clears, or exports the shared instructions text. It also lists and selects copy presets. Selecting a preset requires an explicitly bound tab context.

Export writes the formatted prompt to a file. It does not submit that file to another AI service. A copy-preset override changes the export format. See the [`prompt` contract](../../mcp-server/mcp-tools.mdx#prompt).

![prompt switch and expanded prompt editing, export, and preset operations](../images/tools-prompt.png)

## read_file

Reads a file in full or by line range. Positive `start_line` values are one-based; a negative value reads from the end. With a positive start, `limit` bounds the number of lines.

Reuse returned file paths for reliable lookup, adding a root alias when needed. For worktree-bound sessions, reads use the bound worktree. Approved external read paths remain read-only. See the [`read_file` contract](../../mcp-server/mcp-tools.mdx#read_file).

![read_file switch and expanded path and line-range reading options](../images/tools-read-file.png)

## workspace_context

Returns or exports the current workspace context. The default snapshot includes the prompt, selection, code structure, and token counts. Optional sections can include full file contents or a selected-file tree.

Use include options to control the payload, or a copy-preset override to change rendering and token calculation. `export` writes the rendered context to disk; it does not send that context to an external service. See the [`workspace_context` contract](../../mcp-server/mcp-tools.mdx#workspace_context).

![workspace_context switch and expanded snapshot, export, token, and copy-preset options](../images/tools-workspace-context.png)

## Policy-Gated and Sub-Agent Internal Tools

In addition to the 21 advertised tools above, RepoPrompt defines **10 policy-gated and sub-agent internal tools** that are omitted from this general settings pane and dynamically exposed only within eligible Agent Mode sessions and authorized oversight contexts:

- **`ask_user`** — Prompts the user with structured questions, optional suggested answers, and configurable timeouts.
- **`ask_oracle`** — Consults the configured Oracle model directly from an eligible Agent Mode session.
- **`oracle_chat_log`** — Reads recent Oracle conversation history (`limit` 1–50) during an Agent Mode run without sending a new turn.
- **`agent_session_link`** — Manages cross-window and cross-session communication links, steering, model targeting, and auto-wake snoozing.
- **`session_admin`** — Administers sessions within a user-granted delegation scope, including session tree inspection, organization, worktree binding, and merge coordination.
- **`become_overseer`** — Requests promotion of the calling session to an overseer role to coordinate sibling sessions.
- **`self_compact`** — Requests self-compaction or context inspection (`op="context"` or `"compact"`) of the agent's own session context.
- **`share_thoughts`** — Publishes reasoning thoughts or plan progress to the session timeline.
- **`set_status`** — Updates the human-visible status indicator on the session card.
- **`wait_for_next_user_instruction`** — Signals that the agent has completed its turn and is waiting for the next user instruction.

See [Policy-Gated and Sub-Agent Internal Tools](../../mcp-server/mcp-tools.mdx#policy-gated-and-sub-agent-internal-tools) in the Tools Reference for details.
